# harness-poc

POC of a university AI harness. Master spec: SPEC.md — follow it; where code
and spec conflict, the spec wins; where the spec is silent, choose the boring option.
Production vision: ARCHITECTURE.md — read it before proposing any design not
covered by SPEC.md, and decide in its spirit; for the POC, SPEC.md always wins.

## Commands

- run all: docker compose up --build
- seed:    uv run scripts/seed.py
           then: docker compose restart mcp-colleague mcp-canvas mcp-kuali mcp-labor
           The servers hold the deleted database file open until they are
           restarted, so without this you keep reading the old data.
- seed check: uv run scripts/verify_seed.py
           data/*.db are committed AND generated by seed.py, so the two can drift
           apart silently. This re-seeds into a temp dir (never data/) and compares
           every table logically. Run it after touching seed.py; if it reports
           drift, re-seed and commit data/*.db, or fix seed.py.
- tests:   uv run pytest tests/ -x -q   (stack must be running)
- one svc: docker compose up gateway --build
- pre-demo: docker compose logs --since 30m 2>&1 | grep "dropped" || echo "clean"
Expect "clean". Run it AFTER the test suite, never during: the disruptive
test stops the audit service on purpose, so a run within 30 minutes of the
suite shows an expected auth_failed drop from the gateway. Anything else
means demo moment 9's audit page will be missing rows; the line names the
service and the URL that failed. Drops are debounced to once a minute per
process, so one line can stand for several lost events.

## Deploy (LXC, tunnel profile)

git pull && docker compose --profile tunnel up -d

Set real values for CHAINLIT_AUTH_SECRET_ADVISOR and CHAINLIT_AUTH_SECRET_EXEC
in .env on the LXC. The built-in defaults are fine on localhost and nowhere
else: they sign each Chainlit app's session cookie, and a public tunnel plus a
published cookie secret is a forgeable login. They have no bearing on the
harness JWTs, which identity-stub signs with RS256.

## Working discipline

- **`commit`, `push` and `merge` are the human's words, not yours.** Do not run
  `git commit`, `git push`, `gh pr merge` or any merge unless the human says so
  in that message. Asking for one does not authorise the next: "commit" means
  commit and stop, not commit and push. A green CI run, a trivial diff, an
  obvious next step and a previous instruction three messages ago are all *not*
  permission.
  - Default behaviour: make the change, leave it **unstaged** in the working
    tree, and report what changed and what you verified. Leaving it unstaged
    matters — `git diff` should show the human their own change, not a staged
    one they have to go looking for.
  - Session 17 got this wrong: fourteen commits in one day that were never
    asked for. The work was fine and the presumption was not. Volume is the
    tell — if you are about to commit for the third time without being asked,
    you have stopped collaborating and started driving.
- **Every change goes on a branch.** Never commit to `main` directly, including
  documentation. Branch from `main`, name it for the work (`ci-discipline`,
  `fix-enrollment-trend-order`). Creating a branch needs no permission; putting
  commits on it does.
- **Never merge without explicit confirmation.** Open the PR when asked to,
  report what is in it and what CI said, and stop. Merging is the human's call
  every time, even when CI is green and the change looks trivial.
- **CI must be green before asking.** `ruff check`, gitleaks, the repo checks and
  `docker compose build` all run on every push (`.github/workflows/ci.yml`) and
  need no secrets. The 162-test suite needs a live stack and a paid key, so it
  is manual — `gh workflow run "Full suite (live stack)"` — and its result
  belongs in the PR description when the change touches `services/`, `libs/` or
  `config/`.
- **The lint rule set only grows when the tree is already green for it.** Rules
  and the reason each deferred one is deferred are in `pyproject.toml`
  `[tool.ruff.lint]`. Do not add a rule and a mass reformat in the same change.

### One-time repository setup

```bash
gh secret set DEEPSEEK_API_KEY                 # only suite.yml needs it
gh api -X PUT repos/{owner}/{repo}/branches/main/protection \
  -f 'required_status_checks[strict]=true' \
  -F 'required_status_checks[contexts][]=ruff' \
  -F 'required_status_checks[contexts][]=gitleaks' \
  -F 'required_status_checks[contexts][]=repo checks' \
  -F 'required_status_checks[contexts][]=docker compose build' \
  -F 'enforce_admins=true' -F 'required_pull_request_reviews[required_approving_review_count]=0' \
  -F 'restrictions=null'
```

Branch protection is what makes "never merge without confirmation" a property of
the repository rather than a promise. It cannot be set until the remote exists.

## Hard rules

- Never weaken, mock, or bypass JWT validation — not in dev mode, not in tests,
not "temporarily". Tests use real tokens from identity-stub.
- Every service validates tokens independently via libs/harness_auth. No service
trusts upstream validation.
- Authorization decisions live ONLY in MCP servers (+ registry filtering in the
orchestrator). Never add them to the gateway or UIs.
- Model system prompts are static string constants. Dynamic content goes in
messages after the prefix (DeepSeek prefix caching).
- Python 3.12, uv, type hints everywhere, Pydantic models for every payload.
- Small files, no cleverness. This is a demo that must be readable on a projector.
- The build is complete and certified; there is no `SESSION_REPORT.md` at the
  root and no archive step at session start any more. Session reports live in
  `reports/session-<n>.md`, one per session, Sessions 2 to 17. If further work
  ever warrants a report, write it straight to the next unused
  `reports/session-<n>.md`: what was done, any deviations and why, acceptance
  status per criterion, open questions. It must stand alone — assume the reader
  has no access to this terminal, so include the evidence (commands run,
  outputs, counts), not just conclusions.
